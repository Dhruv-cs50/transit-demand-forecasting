| 1 | `Processing/ablation.py` (`run_inference_with_config`, `run_ablation`) | `run_inference_with_config()` had no `as_of`/context-cutoff at all — unlike its siblings `zero_shot.py`'s `prepare_context()` and `predict.py`'s `_build_context()`, both of which split the feature store into a context window ending at `as_of` and a separate future window. It converted the **entire** `feature_store` argument (train+val+test, through the last real month) straight into `ts_df` and called `predictor.predict(ts_df, prediction_length=...)`. AutoGluon's `TimeSeriesPredictor.predict()` forecasts `prediction_length` steps *after the last timestamp present in the input data* — so every ablation config forecast landed on the 6 months immediately after the full feature store's last month (e.g. Jan–Jun 2024), never on the Jul–Dec 2023 test window `test_df` actually covers. `eval_on_slices()`'s `actuals.merge(preds, on=["timestamp","station_id"], how="inner")` therefore never found an overlapping timestamp, `merged` was always empty, every slice evaluation returned `[]`, `run_ablation()`'s `all_rows` stayed empty, and `main()` hit `if ablation_df.empty: log.error("Ablation produced no results"); return` — the ablation study's entire stated purpose (measuring each covariate group's WAPE/MAE impact) silently produced zero output on every run, for all six configs, regardless of the schema/p50-column fixes already applied to this same function on 2026-07-16 and 2026-08-14/08-18 (those fixed the predictor's *inputs*; this is the third, independent bug in this function — the *time window* being forecast was structurally disjoint from the window being evaluated against). Fixed by giving `run_inference_with_config()` an `as_of` parameter, computed once in `run_ablation()` from `cfg["data"]["val_end"]` (tz-matched to the feature store, same pattern as `benchmarks.py`'s `_match_tz`), and clipping `feature_store` to `timestamp <= as_of` before zeroing/converting — mirroring `zero_shot.py`/`predict.py`'s context-window pattern so `predict()` now forecasts the 6 steps immediately after `val_end`, i.e. the actual test period. | High |
