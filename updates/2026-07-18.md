# Daily Update — 2026-07-18

## Backlog status

- `main` is current through **PR #42** (merged 2026-07-16 audit's fixes).
  This was the first merge since 2026-07-12 — good.
- **PR #43** (2026-07-17 daily audit) is open and unmerged. It re-verified
  #42's fixes (all still correctly applied on `main`) and found three new
  bugs in previously-unaudited ingestion files. Verified today that all
  three are still present on current `main` (PR #43 has not landed) and
  reapplied them directly in this PR rather than waiting on #43 to merge:
  - `machine_learning_files/fetch_events.py`: TBD-time Ticketmaster events
    produced a tz-**naive** timestamp while confirmed-time events and all
    Sharks/NHL rows are tz-**aware** — concatenating both and calling
    `pd.to_datetime()` in `enrich_events()` raises `ValueError: Cannot mix
    tz-aware with tz-naive values`. Fixed by localizing the date-only
    branch to `America/Los_Angeles` too.
  - `machine_learning_files/fetch_bart_od.py` (`download_month`): only
    caught `requests.RequestException`; a 200-status response with a
    non-Excel body (bart.gov soft-404 HTML) let `parse_bart_od_excel`'s
    exception propagate out of the per-month loop and kill the entire
    multi-year batch job. Added a second `except` around the parse call so
    a bad response just falls through to the next candidate URL/month.
  - `machine_learning_files/fetch_511_transit.py` (`get_lines`): read the
    wrong top-level JSON key (`"Content"` instead of `"Contents"`, which
    the sibling `get_stops()` correctly uses) — silently returns empty
    data against a real API response. Dead code today (nothing calls
    `get_lines()` yet), but a live bug the moment it's used.
- PRs **#2–#41** (36 open PRs) remain stale/superseded, per every log
  since 2026-07-17. **Recommend closing all of them** — #42 supersedes
  #2–#24/#28–#37, and this PR supersedes #39–#41/#43. The stale-PR backlog
  itself — not any remaining code bug — continues to be this project's
  biggest risk: verified fixes have sat unmerged for weeks at a time
  across most of this project's history.
