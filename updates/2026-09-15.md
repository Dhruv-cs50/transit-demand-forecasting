| 1 | `evaluation/metrics.py` (`mae`, `rmse`, `mape`, `wape`, `smape`, `mase`) | None of the six core metric functions guarded against `NaN` rows in `y_true`/`y_pred`, unlike `coverage()`/`interval_width()` which were already fixed for this on 2026-09-13. `predict.py`'s own documented fallback (`preds[col] = np.nan` when a model doesn't return a matching quantile column) and partial zero-shot/finetuned forecast failures make `NaN` `p50`/actual values a real, reachable case — `np.mean`/`np.sum` over an array containing even one `NaN` silently return `NaN`, so a single bad row anywhere in a slice poisoned every metric (MAE, RMSE, MAPE, WAPE, sMAPE, MASE) to `NaN` for the **entire** slice, not just that row.
