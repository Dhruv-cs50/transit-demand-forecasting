## Bugs fixed today

Today's pass deliberately skipped the well-covered `machine_learning_files/`,
`Processing/feature_engineering.py`, and `evaluation/` timezone/import bugs above
(already reported ~30 times) and focused on files with little or no prior coverage:
`scripts/export_website_data.py`'s station-code mapping, `website/charts.jsx`,
`models/chronos2/predict.py` + `models/baselines/benchmarks.py`'s mode handling,
`evaluation/metrics.py`, and `Processing/ablation.py`'s covariate schema.

| # | File | Bug | Severity |
|---|------|-----|----------|
| 1 | `scripts/export_website_data.py` (`BART_CODE_TO_WEBSITE_ID`) | Keyed by invented 2-letter codes ("EM", "MT", "12"…) that never match the real 4-letter `station_id` values in the feature store (from `fetch_bart_od.py`'s `STATION_NAMES`, e.g. "EMBR", "MONT", "12TH"). Every lookup returned `NaN`, so `stations_ridership.json` was exported empty — the live map's real-data heat overlay had no data to show. Re-keyed to the actual 4-letter codes. | High |
| 2 | `website/charts.jsx` (Calibration chart) | Filtered `forecasts.json` for `station_id === 'EM'`, but the export writes the real code `'EMBR'`. Filter never matched, so the P10/P50/P90 calibration chart always rendered "No forecast data". Fixed the filter value. | High |
| 3 | `models/chronos2/predict.py` + `models/baselines/benchmarks.py` | `Predictor` is a singleton caching `_mode` on first load; `benchmarks.py` calls it twice expecting one zero-shot run and one fine-tuned run, but both resolved to whichever mode was cached first — silently comparing the same model against itself whenever fine-tuned weights exist, defeating the benchmark. Added a `mode` override threaded through `forecast()` / `forecast_all_stations()` / `_ensure_loaded()`, and passed `mode="zeroshot"` / `mode="finetuned"` explicitly from `benchmarks.py`. | High |
| 4 | `evaluation/metrics.py` (`mase`, `_compute`) | Hardcoded `seasonality=96` (a 15-min/24hr assumption) even though this project's data is monthly BART ridership everywhere else. For any dataset over ~96 rows, MASE silently computed a meaningless scaled error against the wrong lag. Changed default to 12 (annual seasonality for monthly data) and lowered the gating threshold from 96 to 24 rows to match. | Medium |
| 5 | `Processing/ablation.py` (`run_inference_with_config`) | Built the AutoGluon `TimeSeriesDataFrame` using only the active ablation group's covariate columns, dropping the rest entirely instead of keeping them zeroed (as `zero_out_groups()` intends). Every config except `6_full_model` handed the fine-tuned predictor a schema missing `known_covariates_names`, breaking inference for the very configs the ablation study exists to compare. Now includes all covariate columns from every `COVARIATE_GROUPS` entry, only zeroing the excluded ones' values. | Medium (latent — needs a trained AutoGluon model to trigger) |
