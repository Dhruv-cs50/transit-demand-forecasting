# Daily Updates — 2026-06-15

## Bug Fixes Applied

### 1. `predict.py:451` — IndexError on empty slice (HIGH)
**File:** `models/chronos2/predict.py`

`ridership_lift()` had an unguarded `.iloc[0]` on the rain-check filter (line 451) that could
raise `IndexError` when no future rows exist with a rain flag. Fixed by adding an empty-check
guard consistent with the adjacent Sharks-game check.

### 2. `finetune.py:128-130` — No empty-df check before TimeSeriesDataFrame creation (HIGH)
**File:** `models/chronos2/finetune.py`

After `dropna(subset=["target"])`, if all rows had null target the resulting empty DataFrame
would be passed to `TimeSeriesDataFrame.from_data_frame()`, causing a cryptic AutoGluon error.
Added an explicit `ValueError` with a clear message.

### 3. `finetune.py:235` — Redundant `import pandas as pd` inside function body (LOW)
**File:** `models/chronos2/finetune.py`

`build_predictor()` re-imported pandas at line 235 even though it is already imported at module
level. Removed the duplicate import.

### 4. `merge_pipeline.py:185` — `tz_localize(None)` on tz-aware Series (MEDIUM)
**File:** `machine_learning_files/merge_pipeline.py`

`compute_event_features()` used `tz_localize(None)` to strip timezone from an already-aware
`ev_ts` Series (set to `America/Los_Angeles` by `load_events`). In older pandas this raises
`TypeError: Already tz-aware, use tz_convert to convert.` Changed to `tz_convert(None)` for
correctness and consistency with the pattern used elsewhere in the pipeline (e.g., `load_weather`
line 128).

### 5. `api.py:138, 187` — Empty-string timestamp silently included in forecast response (MEDIUM)
**File:** `machine_learning_files/api.py`

Both the cached and live forecast paths used `row.get("timestamp", "")`, meaning a row with a
missing timestamp would produce `{"timestamp": "", ...}` in the JSON response instead of being
skipped. Added a guard to skip rows with missing timestamps and log a warning.
