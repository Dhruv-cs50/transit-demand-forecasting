## Bugs fixed today

These are **new** findings — not previously reported in PRs #1–26, which focused
almost entirely on `machine_learning_files/`, `Processing/feature_engineering.py`,
`evaluation/`, and `models/`. Today's pass covered the previously-unaudited
`website/*.jsx`, `models/baselines/fetch_pems_roads.py`, and `Processing/ablation.py`.

| # | File | Bug | Severity |
|---|------|-----|----------|
| 1 | `Processing/feature_engineering.py` | `HUB_STATIONS` included `"diridon"`, which is never a valid `station_id` (Diridon is a Caltrain/VTA hub, not a BART station in this dataset) — `is_hub_station` could never match it regardless of casing. Removed the dead entry; Diridon proximity is already captured via `dist_from_diridon_km` / `in_event_catchment`. | Medium |
| 2 | `models/baselines/fetch_pems_roads.py` | `_clean_5min()` renamed any column containing `"station"` **or** `"id"` to `sensor_id`. Real PeMS 5-min exports have both a `Station` and a `Station Length` column — both matched, collapsing into two columns named `sensor_id` and turning `df["sensor_id"]` into a DataFrame instead of a Series downstream. Narrowed the match to an exact `"station"` column name. | High |
| 3 | `machine_learning_files/merge_pipeline.py` | Monthly weather aggregation used `.mean()` across all columns including `weather_code`, a categorical WMO code (0=clear, 61=rain, 95=thunderstorm…). Averaging it produces a meaningless fractional value that's fed straight into `finetune.py` as a model covariate. Now takes the modal (most frequent) code for the month instead. | Medium |
| 4 | `Processing/ablation.py` (`event_day_impact_table`) | `grp.get("is_game_day", pd.Series(False))` returns a length-1 default Series with a mismatched index when `is_game_day` is absent, so `grp[... == False]` raises `IndexingError: Unalignable boolean Series provided as indexer`. Replaced with an explicit `"is_game_day" in grp.columns` branch. | Medium |
| 5 | `Processing/ablation.py` (fallback `prediction_length`) | `pd.tseries.frequencies.to_offset(freq).nanos` raises `ValueError` for non-fixed frequencies — and `configs/model.yaml` uses `"MS"` (month-start). Only reachable if both `forecast_horizon_steps` and `prediction_length_steps` are absent from config, but a real crash if so. Added a 30-day-month approximation fallback instead of letting `.nanos` raise. | Low (latent) |
| 6 | `website/sections.jsx` | Demo section copy advertised "Real Leaflet map" / "CartoDB Voyager tiles", but `transit-demo.html` was switched to the Google Maps JS API back on 2026-06-30 (see git log). Updated copy to match the actual implementation. | Low |
