## Bugs fixed today (previously unaudited)

| # | File(s) | Bug | Severity |
|---|---------|-----|----------|
| 1 | `machine_learning_files/api.py` (`_run_forecast`) | The fast/cached forecast path correctly truncates to the client's requested `horizon_hours` (`station_cache.head(horizon_hours)`), but the slow "live Chronos inference" fallback path (hit whenever the nightly `zero_shot_forecasts_*.parquet` cache is missing or has no rows for the station) computed `prediction_length` only from `configs/model.yaml` and ignored `req.horizon_hours` entirely — a client requesting `horizon_hours=1` on this path got back a fixed 6-step forecast while the JSON response still echoed `"horizon_hours": 1`, a response-contract violation reachable on first deploy, for newly-added stations, or after any cache-dir loss. Fixed by capping the forecast call at `min(prediction_length, horizon_hours)`. | Medium |
| 2 | `models/baselines/fetch_pems_roads.py` (`_clean_5min`) | Column renaming matched `"flow"`/`"speed"`/`"occ"` by substring with no lane filter, so Caltrans PeMS's per-lane columns (`"Lane 1 Flow"`, `"Lane 2 Avg Speed"`, `"Lane 1 Avg Occ"`, …) collided with the aggregate `"Total Flow"`/`"Avg Speed"`/`"Avg Occupancy"` columns onto the same three target names — the same duplicate-column collision class already fixed for `"station"` vs `"station length"` on 2026-07-01, this time producing a DataFrame instead of a Series at `df["speed_mph"] < 35` and crashing `--mode live`. Fixed by skipping any column whose name contains `"lane"` before the flow/speed/occ substring checks, keeping only the station-aggregate columns. Only reachable via `--mode live` (interactive PeMS login), so flagged as lower-confidence pending confirmation against a real PeMS export, but the fix is a no-op if the collision doesn't occur. | Low-Medium |
| 3 | `website/app.yaml` + `website/404.html` | `app.yaml` had no `error_handlers:` block, so the leftover Firebase-era `404.html` (its own body says "generated by the Firebase Command-Line Interface") was never wired up after the 2026-05 switch to App Engine Standard — any broken link on the live site fell through to GAE's generic error page instead of the site's branded 404. Added an `error_handlers: - error_code: not_found / file: 404.html` block. | Low |
| 4 | `website/transit-demo.html` | The BART toggle button read "BART · 50 stations" but the `BART` array backing the map only has 41 entries (the VTA button's "39 stations" label matches its array exactly). Corrected the label to "BART · 41 stations". | Low |

All four independently re-verified by reading the exact current file contents (not copied from an audit report) before fixing; #1 was also traced through `zero_shot.py`'s `run_zero_shot_forecast`/`pipeline.predict_df` to confirm `prediction_length` isn't otherwise constrained by `future_df`'s row count.
