Delegated a read-only sweep targeted at the files with the least prior

re-verified two new bugs by reading both producer and consumer code:

| # | File(s) | Bug | Severity |
|---|---------|-----|----------|
| 10 | `models/chronos2/predict.py` (`Predictor._finetuned_forecast`) | `finetune.py` fits the AutoGluon predictor with `known_covariates_names` set (weather forecast, event schedule, calendar columns — always present), which makes `known_covariates` a required argument to `predict()` at inference time. `forecast()` already correctly splits the feature store into `context_df` and `future_df` via `_build_context()` and passes both into `_finetuned_forecast(context_df, future_df, ...)`, but the function's body never referenced `future_df` — it built the `TimeSeriesDataFrame` from `context_df` alone and called `predict(ts_df, prediction_length=...)` with no `known_covariates`. Every forecast in `"finetuned"` mode — the mode that wins automatically the instant `models/chronos2/weights` exists, and the path `scheduler.py`'s nightly `step_forecast()` hits by default — was broken. Fixed by building a `known_covariates` `TimeSeriesDataFrame` from `future_df`, restricted to `self._predictor.known_covariates_names` and the forecast horizon, with a fallback (and warning) to no covariates if `future_df` doesn't cover the full horizon. | **High** |
| 11 | `machine_learning_files/zero_shot.py` (`main`) | The CLI's `--as-of` tz handling still used the old `as_of.tz_localize(None)` pattern — stripping a non-LA tz-aware timestamp's label directly instead of converting to LA wall-clock time first — already fixed in the equivalent code in `api.py` and `predict.py`. Low severity/certainty: the CLI only documents a date-only `YYYY-MM-DD` `--as-of` format, so the buggy branch is reachable only if a caller passes a full tz-aware ISO string outside the documented interface. Fixed with the same `tz_convert("America/Los_Angeles").tz_localize(None)` pattern used elsewhere. | Low |
