## Known issues logged (not fixed today)

- The backlog-consistency problem remains the project's biggest actual
  risk — see "Backlog status" above. Fifth consecutive day flagging this.
- **New watch item:** `machine_learning_files/api.py`'s response-clamping
  pattern uses `max(0.0, float(x))` on quantile values. In Python,
  `max(0.0, nan)` returns `0.0` (NaN loses float comparisons), so if a
  cached parquet ever has a NaN p10/p50/p90, the API would silently return
  `0.0` instead of surfacing/omitting the missing value, the same failure
  class as the `forecasts.json` bug fixed 2026-08-15 but one layer further
  from data export. No currently-reachable path to a NaN quantile was
  found, so not fixed today — worth a `math.isfinite()`-based guard
  (matching the `export_website_data.py` pattern) if this is ever wired to
  a data source that can produce NaN quantiles.
