|---|---------|-----|----------|
| 12 | `website/charts.jsx` (`ROCCurve`/leaderboard bar chart), `website/sections.jsx` (`Benchmarks`) | Both files hardcoded the winning model as the literal string `'AutoETS (AutoGluon)'` for both the friendly-label lookup and the `isBest`/`best` highlight flag. But `models/baselines/benchmarks.py` — the sole producer of `model_comparison.json` via `compute_metrics(..., model_name=...)` — has never emitted that string; the real name is `"AutoGluon_Ensemble"`. Net effect: the leaderboard bar chart never accent-highlights the winning row, and the site prints the raw internal string `"AutoGluon_Ensemble"` to visitors instead of the intended friendly label "AutoETS / AutoGluon (best baseline)". Fixed by changing the key in both files to `'AutoGluon_Ensemble'`. | Medium |
| 13 | `models/chronos2/predict.py` (`Predictor.ridership_lift`) | The "typical for this hour/day-of-week" baseline filtered on `hour_of_day == now.hour` and `day_of_week == now.dayofweek` — meaningless at this pipeline's actual monthly cadence (every timestamp sits at midnight, so hour matching is a no-op and day-of-week matching degenerates into "same weekday the 1st of some other month happened to fall on," an arbitrary ~1/7 slice of history). With the `~is_game_day` exclusion on top, some station/month combos can have zero matching rows, silently producing `typical_median = NaN` and `lift_pct = NaN` with no error — the CLI would print `Lift: nan% vs typical`. Same root-cause class as several already-fixed "hour-scale logic on monthly-cadence data" bugs. Only reachable via `predict.py`'s own CLI today (not yet wired into `api.py` or the website's static "+34%" card), so scoped as Medium rather than High — but the function's own docstring says powering that card is the intent. Fixed by falling back to "same calendar month across other years" when `hour_of_day` has no sub-daily resolution (mirroring the guard already used in `add_time_features`), and by falling back further to the station's overall non-game-day median (instead of returning `NaN`) when even that filter matches nothing. | Medium |
