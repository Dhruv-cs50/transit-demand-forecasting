## Bugs fixed today

| # | File | Bug | Severity |
|---|------|-----|----------|
| 1 | `models/baselines/scheduler.py` | Nightly pipeline scheduler imported from nonexistent modules (`ingestion.fetch_weather_openmeteo`, `ingestion.fetch_events`, `processing.validators`) and shelled out to a nonexistent script path (`processing/merge_pipeline.py`, in **two** places — the `NightlyPipeline.run()` merge step and the `--step merge` CLI branch). Every step of the nightly job would fail with `ModuleNotFoundError` / missing-file. Confirmed still broken on `main`; re-applying the fix from still-unmerged #33 (which only caught one of the two `merge_pipeline.py` sites — the CLI `--step merge` lambda was still broken even there). | High |
| 2 | `models/baselines/benchmarks.py` (`diebold_mariano_test`) | Both `merged_a` and `merged_b` were built by merging the **full** `actuals` frame (every feature column, not just `ridership`) against a 3-column `preds` slice. When `merged_a.merge(merged_b, ..., suffixes=("_a","_b"))` ran, pandas suffixed *every* shared column between the two — not just the intended `p50` — including `ridership` → `ridership_a`/`ridership_b`. The next line, `common["ridership"]`, then raised `KeyError`. This function has no try/except around it (unlike every other stage in `run_benchmarks()`) and fires whenever a fine-tuned Chronos-2 model exists, i.e. exactly the comparison this file's own docstring says produces the headline "Chronos-2 vs. Prophet" MAPE numbers — so the benchmark run crashed before writing the leaderboard/`model_comparison.json` the website consumes. Fixed by narrowing `actuals` to `["timestamp","station_id","ridership"]` before each merge, so only `p50` collides and gets suffixed as intended. | High |
| 3 | `models/chronos2/finetune.py` | `_default_covariate_cols()` (builds the training frame) and `_get_known_covariate_cols()` (tells AutoGluon which columns are known-future) each hardcoded their own copy of the "known-future" column list, and the two had drifted out of sync — `_get_known_covariate_cols()` was missing 8 columns present in the other list (`precip_in`, `weather_code`, `cloud_cover_pct`, `is_very_cold`, `is_very_hot`, `is_windy`, `temp_deviation`, `is_playoff`). Because AutoGluon only treats columns named in `known_covariates_names` as available for the forecast horizon, all 8 — including the playoff flag and most of the weather-forecast signal — were silently downgraded to past-only, weakening the fine-tuned model with no error raised. Fixed by hoisting a single `_KNOWN_FUTURE_COLS` module-level list that both functions now read from, so the two can't diverge again. | Medium |
| 4 | `website/transit-map.jsx` / `website/index.html` | `TransitMap` (and its Leaflet-based helpers) was defined and exported to `window`, but never rendered anywhere in `sections.jsx`/`charts.jsx`/`tweaks-panel.jsx` — confirmed dead since at least 2026-07-01's log and never acted on. `index.html` still loaded the full Leaflet CSS + JS bundle from a CDN purely to support this unused component (the actual live map, `transit-demo.html`, uses the Google Maps JS API and doesn't touch Leaflet at all). Deleted `transit-map.jsx` and removed its `<script>` tag plus the Leaflet `<link>`/`<script>` tags from `index.html` — one less unused library fetched on every page load. | Low |
