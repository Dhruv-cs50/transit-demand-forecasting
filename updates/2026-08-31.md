## Considered but not changed

- `machine_learning_files/fetch_511_transit.py`: `get_stops()` reads the JSON envelope key as `"Contents"` while `get_lines()` reads it as `"Content"` (singular) — a plausible transcription typo between two structurally similar sibling endpoints, but unverifiable without live-API access (network to 511.org is proxy-blocked, unchanged since 2026-07-16). Flagged for visibility, not changed.
- `machine_learning_files/merge_pipeline.py`'s `compute_event_features(venue_proximity_hrs=4.0)` parameter is accepted but never referenced in the function body — same "unreachable/dead parameter" class already accepted for `context_length_hours`, `--freq`, and `benchmarks.py`'s `slices=`; not worth widening the diff.
- `machine_learning_files/zero_shot.py`'s and `models/chronos2/predict.py`'s `--horizon` CLI flag (documented "hours") is effectively dead whenever `cfg["data"]["forecast_horizon_steps"]` is set (always true today) — the step-based config always wins. This exact pattern for `predict.py` was explicitly identified and deliberately left unfixed on 2026-08-14 (fixing it would make an already-known, deliberately-unfixed inverted formula reachable, which is worse). Same reasoning applies to `zero_shot.py`'s identical structure; left alone.
- `Processing/ablation.py`'s `zero_out_groups()` never zeroes `object`-dtype columns, so `transit_mode` (now a known-future covariate per fix #2) is never actually ablated when the "station" group is excluded. Not fixed: `transit_mode` is constant per station_id and AutoGluon's per-item modeling already implicitly encodes station identity via `item_id`, so this doesn't leak meaningfully new information — a cosmetic gap in the ablation study, not a correctness bug.
- `models/baselines/benchmarks.py`'s Diebold-Mariano test uses a plain `scipy.stats.ttest_1samp` without a HAC/autocorrelation-robust variance estimator — a known statistical simplification, not a code-contract bug; left as a modeling-choice nuance.
- `website/charts.jsx`'s `Gauge` component is fully defined and exported but never rendered anywhere — dead code, same low-value class as previously-logged unused constants/parameters; left alone.
- `scripts/export_website_data.py`'s `build_ridership_json()` computes `max_ridership` but never uses it — dead local variable, same class, left alone.
- `docs/ARCHITECTURE.md`'s API endpoint table omits a few fields present in the real `api.py` models, but the table is an abbreviated summary rather than a copy-pasteable example (unlike the README mismatch fixed 2026-08-20); treating the omission as a bug would be over-reaching.
- `ForecastRequest.horizon_hours` being named/described in "hours" while the pipeline is monthly-cadence was re-investigated and re-confirmed not a bug (already settled 2026-08-22 — semantically correct despite the name).
