| # | File(s) | Bug | Severity |

| 1 | `Processing/ablation.py` (`zero_out_groups`) | Column classification for zeroing used raw `df[col].dtype == object` to detect "leave string/categorical columns as-is." Under pandas 3.x — the actually-installed version here (`pandas==3.0.5`); `requirements.txt` pins only `pandas>=2.1.0` with no upper bound, so this is what a fresh install gets today — a plain string column like `transit_mode` gets dtype `str`, not `object`. The `== object` check silently returned `False`, so `transit_mode` fell through to the numeric `else` branch and got overwritten with the float `0.0` in every ablation config that excludes the `"station"` group (4 of 6 configs), contradicting the function's own docstring and feeding `predictor.predict()` a covariate whose dtype no longer matched what the model was fine-tuned on. Fixed by classifying via `pd.api.types.is_bool_dtype`/`is_numeric_dtype` instead of raw dtype-string comparisons, which are correct under both the pandas <3 `object` backend and the pandas ≥3 `str` backend. Verified with a repro showing `transit_mode` stayed `["heavy_rail", "bus"]` post-fix (was `0.0` pre-fix) under both dtype backends, with numeric/bool columns in the same group still zeroing correctly. | High |
| 2 | `evaluation/metrics.py` (`coverage`, `interval_width`) | Neither function guarded against NaN bounds. `predict.py`'s `forecast()` already has a defensive guard that fills an entire station's `p10`/`p90` column with `NaN` when the upstream model doesn't return a matching quantile column — a real, reachable path on a quantile-naming mismatch, the same API-drift class found repeatedly in this project's history. `coverage()`'s `>=`/`<=` comparisons are always `False` against NaN, so an all-NaN interval silently reported `Coverage_%: 0.0` (reads as "never once captured the truth") instead of "undefined." A partial-NaN slice was worse: 2 valid+covered rows out of 4 reported `50%` coverage instead of the correct `100%` of valid rows, while `interval_width()` for the same slice reported flat `NaN` — an internally inconsistent story between the two metrics for the same underlying rows. Fixed both to mask out NaN rows and compute over the valid subset, returning `NaN` only when no valid rows remain. Verified with three repro cases (all-NaN, mixed NaN/valid, fully-valid regression check) — all-NaN now correctly reports `NaN`/`NaN` instead of `0.0`/`NaN`; mixed case now reports `100%`/`10.0` instead of `50%`/`NaN`; fully-valid case unchanged. | Medium-High |
| 3 | `models/baselines/scheduler.py` (`_simple_loop`) | `run_loop()` tries `apscheduler` first, falling back to `_simple_loop(cfg)` on `ImportError` — and `apscheduler` isn't listed in `requirements.txt` nor installed here, making this fallback the actual `--loop` code path today, not a rare edge case. `_simple_loop` accepted `cfg` but never used it, hardcoding `now.replace(hour=2, minute=0, ...)`. Editing `configs/model.yaml`'s `serving.nightly_refresh_cron` away from its `"0 2 * * *"` default had no effect in `--loop` mode — it silently kept firing at 2am. Currently latent only because the shipped default happens to also be 2am. Fixed to parse `hour`/`minute` from `cfg`'s cron string the same way `run_loop()` already does. Verified with a repro showing the pre-fix logic always computed `02:00` regardless of a `03:30`-configured cron, and the post-fix logic correctly computes `03:30` for that config while still defaulting to `02:00` unset. | Medium |
| 4 | `website/styles.css` (hero section rules) | `#hero`/`#hero::before` selectors matched no element in the DOM — `Hero()` in `sections.jsx` renders `<section id="overview">` (the id doubles as Nav's scroll-spy/anchor target, so it can't be renamed to match the CSS). Confirmed via a full cross-check of every `#id` CSS selector against every `id="..."` actually emitted across `sections.jsx`/`charts.jsx`/`tweaks-panel.jsx`/`index.html` that `#hero` was the sole orphaned selector site-wide. Every visitor's homepage hero silently lost its custom asymmetric padding (falling back to the generic `section{padding:120px 0}` rule) and its entire atmospheric background (two radial-gradient glows meant to sit behind the hero copy via `::before`) — since whatever earlier change unified the section id to `"overview"` for the nav system without updating the paired CSS. Fixed by renaming both selectors (including the mobile media-query override) to `#overview`/`#overview::before`, with a comment explaining the mismatch so it isn't "fixed" back the wrong way later. | Medium |
