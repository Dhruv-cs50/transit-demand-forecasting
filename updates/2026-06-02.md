# Daily Updates — 2026-06-02

## Bug Fixes

### 1. `merge_pipeline.py` — tz_localize → tz_convert (crash on tz-aware data)
**Files:** `machine_learning_files/merge_pipeline.py`  
**Severity:** High — would crash at runtime whenever timestamps carry timezone info  
**Root cause:** Calling `.dt.tz_localize(None)` on a timezone-aware Series raises `TypeError: Already tz-aware, use tz_convert to convert.` The correct method is `.dt.tz_convert(None)`, which strips the timezone after converting to UTC.  
**Locations fixed:**
- `compute_event_features()` — `ev_ts` and `ts_series` strips (lines 185, 191)
- `build_feature_store()` — weather `wdf["timestamp"]` strip (line ~270)
- `build_feature_store()` — base `base_ts` strip (line ~286)
- `make_splits()` — `ts` strip (line ~340)

### 2. `export_website_data.py` — tz_localize → tz_convert (crash on tz-aware timestamps)
**File:** `scripts/export_website_data.py`  
**Severity:** High — `export_ridership_actuals()` crashes when the feature store has tz-aware timestamps  
**Root cause:** Same class of bug as above. Also replaced the fragile `hasattr(ts, "tz")` guard with the correct `ts.tzinfo is not None` check.

### 3. `api.py` — NaN fallback in slow-path forecast (sends null to frontend)
**File:** `machine_learning_files/api.py`  
**Severity:** Medium — when quantile columns are missing in live Chronos inference, p10/p50/p90 were set to `float("nan")`, which serialises as `null` in JSON and breaks the frontend chart. Changed to `0.0` to match the fast-path (cached) behaviour.

### 4. `metrics.py` — non-deterministic station sort
**File:** `evaluation/metrics.py`  
**Severity:** Low — `per_station_metrics()` sorted only by WAPE, producing unstable ordering when two stations tie. Added `station_id` as secondary sort key.

### 5. `validators.py` — incorrect positional index for gap_start lookup
**File:** `evaluation/validators.py`  
**Severity:** Low — `check_missing_windows()` used `grp.loc[idx - 1]` to get the timestamp before a gap, which assumes sequential integer index labels. After `sort_values`, the index labels can be non-sequential. Replaced with `grp.index.get_loc(idx)` for correct positional lookup.
