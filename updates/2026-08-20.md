- The backlog-consistency problem remains the project's biggest actual

- **Station-code convention landmine between `export_website_data.py` and
  the 2026-08-19 `sections.jsx`/`charts.jsx` fix.** `merge_pipeline.py`
  confirms the *current* pipeline's `station_id` is the 4-letter BART code
  (e.g. `EMBR`), and `export_website_data.py`'s `BART_CODE_TO_WEBSITE_ID`
  dict is keyed on 4-letter codes to match. But `export_ridership_actuals()`
  /`export_forecasts()` write the raw `station_id` straight through with no
  mapping — so the *next* real run of `scripts/run_pipeline.sh` (step 7)
  would regenerate `forecasts.json`/`ridership_actuals.json` with 4-letter
  codes, silently breaking the 2026-08-19 `dataId` fix in
  `sections.jsx`/`charts.jsx`, which was written to match the
  currently-committed *2-letter*-coded static files (themselves a leftover
  from before PR #39's 2026-07-13 station-code migration). Today's data
  files and JS are self-consistent and not broken right now. Not fixed:
  there's no feature store/data pipeline in this sandbox to actually
  regenerate and test either side, and correcting either direction requires
  a judgment call about which convention is meant to be canonical going
  forward — better made by a human, or verified against a live pipeline
  run, than guessed at here. Flagged for the next audit that has pipeline
  access.
