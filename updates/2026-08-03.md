Fixed by having `_ensure_loaded` return the effective mode without mutating the cached `self._mode` on a forced call, moving the `self._mode = "finetuned"/"zeroshot"` assignment out of the loader helpers and into the auto-select branch only, and having `forecast()` use the returned `mode` value instead of re-reading `self._mode`. |
| 6 | `machine_learning_files/merge_pipeline.py` (`load_weather`) | Only globbed `weather_all_stations_*.parquet` (the historical-archive output). `fetch_weather_openmeteo.py`'s `fetch_forecast_all_stations()` — run nightly by `scheduler.py`'s weather step specifically to keep forward-looking covariates current — writes to a completely different pattern, `weather_forecast_{run_ts}.parquet`, that nothing in the repo ever read.
