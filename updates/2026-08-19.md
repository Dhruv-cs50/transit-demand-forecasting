## Bugs fixed today

Delegated a fresh, full-file read of the areas that have gotten the least
attention across this month-long audit chain — `website/tweaks-panel.jsx`,
the BART/weather/511/PeMS fetchers, the baseline models, `evaluation/`, and

| # | File(s) | Bug | Severity |
|---|---------|-----|----------|
| 1 | `website/sections.jsx` (`BARTForecasts`, the "Real BART Data" homepage section) | `KEY_STATIONS` used 4-letter BART codes (`EMBR`, `MONT`, `12TH`, `BERY`, `FRMT`) to filter `website/data/forecasts.json` / `ridership_actuals.json`, but those static exports actually carry the short `bart_id` codes from `stations_meta.json` (`EM`, `MT`, `12`, `BE`, `FM`) — a legacy convention that predates the pipeline's later switch to 4-letter codes. Every one of the 5 station buttons produced an empty historical/forecast table; verified against the real committed JSON that 0 rows matched any 4-letter code. The 4-letter codes are still correct and required for this same component's live Cloud Run `/forecast` call, so fixed by adding a `dataId` (short code) alongside `id` (4-letter) per station, using `dataId` only for the static-JSON filters. Re-verified: all 5 stations now resolve 36 actuals rows + 6 forecast rows each. | High |
| 2 | `website/charts.jsx` (`Calibration`) | Same root cause as #1, independently present in a second component: filtered `forecasts.json` for `station_id === 'EMBR'` against data that actually uses `'EM'`. This is the homepage's "Intervals" calibration chart — it rendered "No forecast data" for every visitor. Fixed the filter to `'EM'`, matching the code actually shipped in the committed data file. | High |
| 3 | `models/baselines/fetch_pems_roads.py` (`fetch_pems_bay_dataset`) | `pd.cut(df_long["speed_mph"], bins=[0,15,35,55,999], labels=[...])` has no `include_lowest=True`, so pandas' default left-open first bin excludes a reading of exactly `0` mph — confirmed empirically (`pd.cut([0.0], bins=[0,...])` → `NaN`). Real PeMS sensors legitimately report `0` mph during stalls/incidents, so those rows got `congestion_level = "nan"` (via the trailing `.astype(str)`) instead of `"stop_and_go"`. Added `include_lowest=True`. | Low |
| 4 | `models/chronos2/predict.py` (`main()` CLI summary print) | `f"{lift.get('lift_pct', 'N/A'):+.1f}%"` defeats its own fallback: when `ridership_lift()` returns `{}`, `.get()` yields the string `'N/A'`, which then hits the `:+.1f` numeric format spec and raises `ValueError` instead of printing "N/A". Identical defeated-fallback defect to the one fixed in `finetune.py` on 2026-08-18, independently present here. Fixed with an explicit `None` check before formatting. | Low |

All four fixes independently re-verified before applying — the two
