## Considered but not changed

- `Processing/feature_engineering.py::add_weather_features`'s
  `df["is_raining"] = df["precip_mm"] > 0.1` silently evaluates to `False`
  (not `NaN`) when `precip_mm` is `NaN` — confirmed with a repro
  (`pd.Series([1.0, np.nan, 5.0]) > 0.1` → `[True, False, True]`). Only
  reachable when weather data is missing for *every* monitoring station in a
  given month (both the direct-match and regional fallback empty), a rare
  full-outage scenario distinct from the per-station fallback bug fixed
  2026-08-26. Real but low-confidence/low-impact; not fixed today.
- Re-checked `Processing/ablation.py`'s exact-string quantile-column rename
  (`{"0.1": "p10", "0.9": "p90"}`) against `predict.py`'s fuzzier
  `"0.1" in str(c)` matching — inspected the installed
  `autogluon.timeseries==1.6.1` wheel source directly; every
  quantile-forecasting model constructs output columns via `str(q)`, so the
  exact-string rename is correct as written. Not a bug.
- Re-checked `models/chronos2/finetune.py::evaluate_event_days`'s
  `~feature_store["is_game_day"]` for the bool-dtype-promotion bug class
  fixed 2026-09-14 — traced its construction in
  `merge_pipeline.py::compute_event_features()`: built via `pd.concat()` of
  dict-rows containing only genuine Python `True`/`False`, never
  left-joined (unlike the `has_sharks` case that was actually broken), so it
  stays real `bool` dtype and `~` is correct. Not a bug.
