  here for awareness in case an upstream change ever makes these reachable.

  `full_ts` (train+val) — the same data just used as `tuning_data` for
  AutoGluon's model/ensemble selection — so the reported validation metrics
  carry a mild optimism bias for ensemble weighting specifically. Not a bug:
  this is standard AutoML practice, doesn't produce factually wrong numbers,
  and the project's real held-out reporting comes from the separate, untouched
  `test.parquet` split via `evaluation/metrics.py`. Noted as a methodology
  nuance, not fixed.

  `context_input`/`future_input` are computed but never used — the function
  rebuilds `context_long`/`future_long` separately and passes those to
  `predict_df()` instead. Dead code, not a behavioral bug; not worth widening
