# Daily Updates — 2026-06-26

## Bug Fixes

### Critical — Runtime crashes

**1. `tz_localize(None)` on timezone-aware timestamps (3 files)**

Calling `.dt.tz_localize(None)` on a Series that already has timezone info raises `TypeError` in pandas. Fixed to use `.dt.tz_convert(None)` (strips timezone after converting to UTC), which is the correct approach.

- `machine_learning_files/merge_pipeline.py` — `compute_event_features()`: two callsites (lines ~185, ~191)
- `scripts/export_website_data.py` — `export_ridership_actuals()`: per-row timestamp strip

**2. Wrong Chronos class name in zero-shot fallback (`models/chronos2/predict.py`)**

`Predictor._load_zeroshot()` imported `Chronos2Pipeline` — a name that does not exist in the `chronos` package. The correct class is `ChronosPipeline` (same as used in `machine_learning_files/api.py`). This caused a silent `ImportError`, meaning the predictor always fell back to the seasonal naive model instead of using Chronos-2.

---

### Significant — Wrong results / incorrect behavior

**3. `auto_arima` seasonal period wrong for monthly data (`models/baselines/arima.py`)**

`fit_auto_arima()` set `s = 24 if "h" in freq else 96`. For monthly frequency (`"MS"`, `"M"`), neither branch matched, so `s` defaulted to 96 (a 96-month = 8-year seasonal period). Fixed to detect monthly frequency first and set `s = 12`.

**4. Timezone-aware vs naive comparison in date range filter (`machine_learning_files/merge_pipeline.py`)**

`build_feature_store()` compared `base["timestamp"]` (timezone-naive, stripped earlier in the pipeline) against `pd.Timestamp(start, tz="America/Los_Angeles")` (timezone-aware). This raises `TypeError` at runtime whenever `--start` or `--end` CLI args are passed. Fixed to use tz-naive `pd.Timestamp(start)`.

---

### Minor — Dead code / deprecation warnings

**5. `n_new` always zero in `build_features()` (`Processing/feature_engineering.py`)**

`n_new = n_features - len(df.columns)` subtracted the same value from itself. Fixed to capture the column count before transformations (`n_cols_before`) and use that as the baseline, so the log now correctly reports how many new columns were added.

**6. Unused `YEAR_MONTH_FORMAT` dict removed (`machine_learning_files/fetch_bart_od.py`)**

A dict of URL patterns keyed by `range(...)` objects was defined but never referenced — `build_url_candidates()` hardcodes the URL templates directly. Removed.

**7. `datetime.utcnow()` replaced with `datetime.now(timezone.utc)` (2 files)**

`datetime.utcnow()` is deprecated since Python 3.12 (the runtime targeted by `website/app.yaml`). Replaced with `datetime.now(timezone.utc)` throughout:
- `machine_learning_files/api.py` (2 callsites: `/health` and `/forecast`)
- `models/chronos2/predict.py` (`forecast()` method)

**8. Deprecated FastAPI `@app.on_event("startup")` replaced with `lifespan` (`machine_learning_files/api.py`)**

`on_event("startup")` is deprecated since FastAPI 0.93. Replaced with the `asynccontextmanager`-based `lifespan` function passed to `FastAPI(lifespan=...)`. Behavior is identical — pre-loads the feature store on startup and retries on first request if it fails.
